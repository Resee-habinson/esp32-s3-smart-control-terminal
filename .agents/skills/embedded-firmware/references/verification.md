# 验证策略

## 选择检查

- 先使用仓库已经定义的格式化、编译、测试、静态分析和硬件测试流程。
- 根据变更风险选择最小但充分的验证，不为文档修改运行无关的完整硬件测试。
- 不把“命令成功退出”等同于功能正确；检查警告、测试数量和生成物。

## 嵌入式专项

- 编译所有受影响配置、板型和条件编译分支；无法覆盖时列出未验证组合。
- 检查链接结果、RAM/Flash、各任务栈和关键段布局是否超预算。
- 对并发与 ISR 修改检查竞态、死锁、优先级反转、重入和最坏执行时间。
- 对硬件交互验证超时、复位、掉电、断连、错误中断和设备缺失路径。
- 对协议和存储格式使用边界值、损坏数据、版本兼容和字节序测试。

## 交付证据

- 记录实际执行的命令及结果摘要。
- 区分已验证、静态推断和未验证内容。
- 硬件不可用时提供最接近的主机测试、模拟或代码级检查，并明确其局限。
