# C/C++、资源与执行上下文

## 风格和可维护性

- 使用仓库的格式化工具和邻近代码风格；用户要求教学型详细中文注释或仓库没有注释规范时，使用 [commenting.md](commenting.md)。
- 注释说明步骤、硬件配置、参数作用、数值来源、引脚、电平、单位、线程语义和注意事项。
- 为自研函数添加统一中文函数头；对关键硬件配置语句使用右侧中文注释。
- 不自动加入作者、日期或手工版本号等易过期文件头。
- 避免魔法值，但允许语义显然的常量，如循环零值或布尔比较。

## 数据类型

- 对寄存器、协议、持久化布局、位运算和明确范围使用固定宽度整数。
- 对标准库接口、自然机器字和普通循环，允许使用合适的原生类型。
- 明确单位、符号、溢出、截断、对齐、字节序和整数提升风险。
- 不把结构体内存布局直接作为线协议，除非布局、对齐和字节序已有契约。

## 内存和生命周期

- 根据生命周期、大小、所有权、重入性和并发选择栈、静态区、池或堆。
- 不仅因为对象较大就改成函数内 `static`；先检查任务栈预算和并发访问。
- 动态内存并非绝对禁止。实时路径应避免不可预测分配；允许使用时定义失败处理、碎片策略和所有权。
- 大缓冲区优先考虑调用者提供、模块实例持有或固定内存池。

## 并发与 ISR

- `volatile` 只表达特定可见性或硬件访问意图，不提供原子性、互斥或内存同步。
- 明确数据由任务、ISR、DMA 还是多核访问，并选择原子、临界区、锁、队列或所有权转移。
- ISR 必须有界、非阻塞并使用 ISR-safe API；避免格式化日志、动态分配和复杂业务。
- 检查锁顺序、优先级反转、回调重入和中断与任务之间的竞态。

## 实时性与性能

- 使用测量结果和预算优化 CPU、RAM、Flash、栈和延迟。
- 避免无等待忙轮询；硬件要求短暂轮询时，加入有依据的超时。
- 时间计算使用适合计数器回绕的差值方式。
- 优化后保留可读性，并验证最坏情况而不只验证平均情况。
