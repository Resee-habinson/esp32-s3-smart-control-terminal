# API 设计

## 先定义契约

公开 API 应根据需要明确：

- 功能及不可变条件
- 输入、输出、范围、单位和缓冲区容量
- 数据所有权、生命周期和别名规则
- 成功、失败、部分完成和超时语义
- 阻塞性、可重入性、线程安全性及 ISR 可调用性
- 初始化顺序、允许状态和重复调用行为
- 回调执行上下文及回调期间允许的操作

## 设计原则

- 使用语义明确的名称，并与仓库命名体系一致。
- 保持单一、可测试的职责，但不要把一次原子操作机械拆成大量接口。
- 对只读输入使用 `const`；它不表示对象不会被其他执行上下文修改。
- 根据对象大小、ABI、失败语义和易用性选择值返回或输出参数，不强制所有结构体通过指针返回。
- 参数较多时评估配置结构体；不要以固定数量作为硬性限制。
- Getter 默认不产生隐藏状态变化；读取即清除寄存器等硬件语义必须写入契约。

## 封装与兼容性

- 模块内部状态默认不暴露。优先使用不透明句柄、查询接口、命令或事件。
- 不允许调用者长期保存短生命周期缓冲区或异步 API 的栈地址。
- 扩展配置结构体时考虑版本、大小字段、默认值和旧调用者行为。
- 修改公开符号、枚举值、结构体布局或回调签名前检查源代码与二进制兼容性。

## 异步接口

- 根据负载、丢失策略和耦合程度选择回调、队列、事件、轮询或 future-like 机制。
- 明确队列满、重复事件、取消、超时和对象销毁期间的行为。
- 回调注册需定义是否允许重复注册、注销、并发触发和在回调内重新调用模块。
