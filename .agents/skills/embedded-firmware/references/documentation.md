# 文档同步

## 更新原则

- 仅在行为、接口、配置、构建步骤、架构或运维方式发生变化时更新相关文档。
- 将代码、测试和生成配置视为首选事实来源；避免复制容易过期的细节。
- 遵循仓库现有语言、标题和文档工具，不强制统一为中文。
- 说明设计原因、约束和用户可观察行为，不逐行复述实现。

## 按变更选择文档

- 新用户入口或构建方式：更新 README 或入门文档。
- 公开 API：记录参数、单位、所有权、失败、并发和示例。
- 配置：记录默认值、范围、单位、生效时机、持久化和兼容性。
- 架构：记录职责、依赖和重要决策，不为小改动重画整套架构。
- 协议或持久化格式：记录版本、字节序、长度、校验和迁移策略。
- 状态机：复杂时提供转换表或 Mermaid/ASCII 图，并保证图与代码一致。

## 质量检查

- 验证命令、路径、符号名和默认值与实现一致。
- 标明平台或版本限制，删除已失效说明。
- 若仓库自动生成 API 文档，优先修改生成源而不是生成结果。
- 最终报告实际更新的文档；没有必要更新时无需制造文档改动。
