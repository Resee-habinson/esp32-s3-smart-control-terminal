# 日志与诊断

## 接口和级别

- 使用项目统一日志接口；缺少接口时先提出最小设计，不在各模块散布平台输出函数。
- DEBUG 记录开发诊断，INFO 记录重要生命周期，WARN 记录可恢复异常，ERROR 记录当前操作失败，FATAL 仅用于无法继续安全运行的故障。
- 选择级别时依据影响，不依据开发者主观紧张程度。

## 内容

- 根据系统能力记录稳定事件标识、模块、操作、结果、错误码和关键上下文。
- 优先使用可检索的稳定字段；自然语言遵循项目现有语言，不强制全部中文或英文。
- 不依赖日志文本驱动业务逻辑；关闭日志不得改变程序行为。
- 避免在多个抽象层重复记录同一错误。

## 安全

- 在任何构建中都不得记录完整密码、私钥、Token、证书私密材料或个人敏感数据。
- 对设备标识、地址、载荷和认证信息应用删除、截断、哈希或掩码策略。
- 将日志视为可能被导出和长期保存的数据。

## 性能和上下文

- 高频路径使用状态变化记录、采样、限频或聚合，不逐次打印。
- ISR 默认只记录轻量事件或计数，并交由任务输出；仅使用平台明确标注为 ISR-safe 的设施。
- 考虑格式化成本、锁竞争、串口阻塞、缓冲区溢出和日志丢失策略。
- 发布构建按需求保留必要 WARN/ERROR，而不是默认假设所有日志都可关闭。
