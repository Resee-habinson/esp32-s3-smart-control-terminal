# 错误处理与恢复

## 错误模型

- 区分编程错误、无效输入、暂时故障、永久故障、业务状态和硬件安全故障。
- 对可能失败的公开操作提供明确结果；沿用项目现有错误类型，不强制所有模块共享单一枚举。
- 不用错误码表达“无数据”“未按键”等正常状态，除非 API 契约明确将其定义为结果状态。

## 检查与传播

- 在信任边界和公开接口检查可能违反契约的输入；热路径内部函数可依赖已经验证的不变量。
- 显式处理影响正确性的返回值。确需忽略时使用仓库认可的方式表达意图。
- 下层保留原始原因；上层在抽象边界处翻译错误并补充上下文，不机械泄露硬件细节。
- 避免同一错误在每一层重复记录日志。

## 清理

- 明确每项资源的所有者，并保证所有退出路径释放锁、句柄、缓冲区和外设状态。
- 简单路径可以提前返回；多资源函数可以使用统一清理块，避免复制清理代码。
- 清理操作本身可能失败时，定义主错误与清理错误的优先级。

## 重试与恢复

- 仅对暂时且可安全重试的操作进行重试。
- 定义最大次数或截止时间、退避、抖动、幂等性和取消条件。
- 不在 Driver 中擅自决定业务级重试策略；底层提供原因，上层依据上下文决策。
- 不可恢复或安全相关故障应进入已定义的安全状态，如关闭输出、停止电机或隔离通信。

## 断言

- 使用断言发现理论上不可达的程序错误，不用断言替代外部输入检查。
- 明确发布构建中断言关闭或触发后的行为，避免关闭断言改变必要控制流。
